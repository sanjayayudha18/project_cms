# 5.1 Parameter Cash Count + Mapping PIC
> Status: accepted 2026-11-12 (user)

Sumber: `.document/DSR End To End Cash Management V01.md` §A.5.1 L489–L658 (tanpa L595–L615 "Metode Kunjungan" dan L660–L685 "Frekuensi Kunjungan" → fase 5.3) · Prasyarat: 5.0 K4, K6, K7, K8, K12, K15 · Ukuran: M

## Tujuan & Scope
Menyediakan semua master data yang dibutuhkan fase cash count lain: parameter kategori vault H/M/L, kategori ATM Anomaly, item checklist Berita Acara, area cash count, dan mapping PIC Coordinator/Executor — semuanya lewat maker-checker dengan audit before/after — plus 7 peran baru `CC-*`.
- Masuk: tabel + migrasi `041`, peran + menu, CRUD maker-checker 5 entitas, fungsi klasifikasi H/M/L (dipakai 5.3), upload CSV replace-all + download CSV mapping PIC, layar CompanyPortal, kontrak OpenAPI.
- Tidak termasuk: perhitungan rata-rata saldo + rencana kunjungan acak (5.3); ambang selisih Rp10 juta + daftar penerima email (5.5/5.8, K11); isi checklist dari lampiran FSD (K15 — tanpa seed); jenis jawaban checklist (5.5/5.7); atribut STCC (lihat Pertanyaan Terbuka).

## Acceptance Criteria
- **AC-5.1-01** (L497–L520, K4): `CC-CWM` dapat mengajukan satu set parameter kategori vault berisi batas bawah Medium (inklusif), batas atas Medium (inklusif; di atasnya High), mata uang IDR, dan jumlah kunjungan onsite per 6 bulan untuk High, Medium, Low. Seed awal dari FSD: 5.000.000.000,00 / 15.000.000.000,00 / High 3, Medium 2, Low 1.
- **AC-5.1-02** (L516–L520, K4): klasifikasi total saldo: saldo < batas bawah Medium → LOW; batas bawah ≤ saldo ≤ batas atas → MEDIUM; saldo > batas atas → HIGH. Perbandingan presisi penuh (numeric), tanpa float.
- **AC-5.1-03** (L509): jumlah onsite tiap kategori 0–6 (periode tetap 6 bulan); batas bawah > 0 dan batas bawah < batas atas. Input yang melanggar → 422 dengan pesan bahasa Indonesia.
- **AC-5.1-04** (L534): set parameter baru berlaku hanya setelah disetujui checker; saat apply, set lama ditandai digantikan dalam tx yang sama, sehingga selalu tepat satu set aktif. Riwayat set lama tetap bisa dilihat.
- **AC-5.1-05** (L538–L557, K12): `CC-CCR` dapat membuat, mengubah, menonaktifkan, dan mengaktifkan kembali kategori ATM Anomaly (kode unik, nama, deskripsi opsional) lewat maker-checker; daftar "aktif" hanya menampilkan kategori aktif.
- **AC-5.1-06** (L561–L581): `CC-CCR` dapat mengelola item checklist Berita Acara: teks, kategori `SELECTED_MACHINE` atau `NON_MACHINE`, nomor poin, dan — hanya untuk `SELECTED_MACHINE`, wajib — hari `DAY1` (mesin) atau `DAY2` (vault). Nomor poin unik di antara item aktif dengan (kategori, hari) yang sama. Create/update/disable/enable lewat maker-checker.

- **AC-5.1-08** (L628, K6): `CC-CWM` dapat mengelola area cash count (kode unik, nama, daftar `region_code`) lewat maker-checker. Satu `region_code` hanya boleh milik satu area aktif; `region_code` harus dipakai minimal satu `vendor_branches` aktif (L648).

- **AC-5.1-13** (L534, L656): setiap perubahan di AC-01–AC-11 tercatat di `audit_logs` dengan maker, checker, dan before/after, dalam tx yang sama dengan perubahan.

## Design
### Data
Migrasi **`041_cash_count_parameters.sql`** (nomor bebas — terakhir `040`), satu tx, forward-only, rollback terdokumentasi di header:

1. **`roles`**: 7 peran `CC-*` (AC-14). **`menu_features`**: `cash-count.parameters` ("Parameter Cash Count"), `cash-count.pic-mapping` ("Mapping PIC") di bawah menu `cash-count` yang sudah ada (id 7). **`role_permissions`**: `ADMIN` keduanya; `CC-CWM` keduanya; `CC-CCR` `cash-count.parameters`; semua `CC-*` menu `cash-count`.
2. **`cash_count_category_params`** — satu baris = satu set (bukan satu baris per kategori, supaya batas tidak bisa bercelah/tumpang tindih; draft `data-map.md` disederhanakan):
   `id bigint identity · medium_min_amount numeric(20,2) NOT NULL CHECK (> 0) · medium_max_amount numeric(20,2) NOT NULL · currency_code char(3) NOT NULL DEFAULT 'IDR' CHECK (= 'IDR') · onsite_high smallint · onsite_medium smallint · onsite_low smallint` (masing-masing `NOT NULL CHECK (BETWEEN 0 AND 6)`) `· period_months smallint NOT NULL DEFAULT 6 CHECK (= 6) · created_by bigint FK users · effective_from timestamptz NOT NULL DEFAULT now() · superseded_at timestamptz NULL · created_at`. CHECK `medium_min_amount < medium_max_amount`. Unique parsial `WHERE superseded_at IS NULL` (satu set aktif). Seed 1 baris (AC-01).
3. **`cash_count_anomaly_categories`**: `id · code text UNIQUE CHECK (^[A-Z0-9_]{2,20}$) · name text CHECK (1–100) · description text NULL CHECK (≤ 500) · is_active · deleted_at · created_at · updated_at`.
4. **`cash_count_checklist_items`**: `id · category text CHECK (SELECTED_MACHINE|NON_MACHINE) · day text NULL CHECK (DAY1|DAY2) · point_no smallint CHECK (> 0) · item_text text CHECK (1–500) · is_active · deleted_at · created_at · updated_at`. CHECK `(category = 'SELECTED_MACHINE') = (day IS NOT NULL)`. Unique parsial `(category, COALESCE(day,''), point_no) WHERE is_active`.
5. **`cash_count_areas`** *(nama baru, perlu persetujuan — lihat Gerbang)*: `id · code text UNIQUE CHECK (^[A-Z0-9_]{2,20}$) · name text CHECK (1–100) · is_active · deleted_at · created_at · updated_at`.
6. **`cash_count_area_regions`** *(nama baru, perlu persetujuan)*: `area_id bigint FK cash_count_areas · region_code text PRIMARY KEY CHECK (^[A-Z0-9]{2,10}$) · created_by FK users · created_at`. PK pada `region_code` = satu region satu area (pola `acm_area_regions`, migrasi 030). Link table murni — ditulis ulang oleh applier area; dikecualikan dari `no_hard_delete_test` seperti `branch_coverage_areas`.
7. **`cash_count_pics`**: `id · pic_role text CHECK (COORDINATOR|EXECUTOR) · user_id FK users NOT NULL · region_code text NULL · area_id FK cash_count_areas NULL · is_active · deleted_at · created_at · updated_at`. CHECK `(pic_role='COORDINATOR' AND region_code IS NOT NULL AND area_id IS NULL) OR (pic_role='EXECUTOR' AND area_id IS NOT NULL AND region_code IS NULL)`. Unique parsial `(pic_role, user_id, COALESCE(region_code,''), COALESCE(area_id,0)) WHERE is_active`.
8. **`export_jobs`**: kind `cash_count_pics` ditambahkan ke `export_jobs_kind_chk` (pola migrasi `037`).

Region memakai `vendor_branches.region_code` (kode bersih yang sudah dipakai Area ACM), bukan `regions` (wilayah ATM).

### Backend / API
Pola master-data maker-checker (`/cms2-master-data`, referensi `dsr_location_map`): queries → repo read-only → service validasi + `Submit` → `Applier` → registry `main.go` → handler 202. Flat JSON. Entity type: `cash_count_category_params`, `cash_count_anomaly_category`, `cash_count_checklist_item`, `cash_count_area`, `cash_count_pic`.

- **Engine (perubahan kecil, area auth)**: `authorizeMasterDataMaker` saat ini hanya menerima `ADMIN`/`ADMIN_PARAM`. Ditambah peta peran maker per entity type: entitas `cash_count_*` memakai `CC-CWM` (category params, area, PIC) atau `CC-CCR` (anomaly, checklist); entity type lain tidak berubah. Checker tetap dari rantai approval yang ada (AC-15).
- **Category params**: hanya op `create` (= ajukan set baru); applier menutup set aktif (`superseded_at = now()`) lalu menyisipkan set baru, satu tx. `GET` mengembalikan set aktif + riwayat. Fungsi murni `ClassifyCashCountVault(total, params) (HIGH|MEDIUM|LOW)` memakai `math/big` (pola `vendor_vault_admin.go`).
- **Area**: payload memuat `region_codes[]`; applier menulis ulang `cash_count_area_regions` untuk area itu. Disable area ditolak (409) bila masih ada PIC executor aktif di area itu.
- **PIC**: validasi AC-09 di submit **dan** dijaga ulang di INSERT/UPDATE applier (user/area bisa berubah antara submit dan approve → 409).
- **Upload CSV PIC**: entitas baru di engine impor master data (`master_data_import_batches`, satu batch satu approval, idempotent SHA-256). Kolom: `pic_role,username,region_code,area_code`. Mode replace-all khusus entitas ini: mapping aktif yang tidak ada di file di-stage sebagai `disable` dalam batch yang sama (engine sudah punya op `disable`).
- **Download CSV PIC**: entitas `cash_count_pics` di `pkg/csvexport` + kind ekspor di `backend-exq` (pola master data export X.7), header = kolom upload.
- **Route** (`/api/v1/cash-count/…`): `category-params` (GET, POST), `anomaly-categories`, `checklist-items`, `areas`, `pics` (masing-masing GET, POST, `PUT /{id}`, `POST /{id}/disable`, `POST /{id}/enable`). Grup route dengan `RequireRoles` sesuai peran maker + `ADMIN` untuk baca; ubah tetap dicek di service.
- **OpenAPI**: modul baru → path di `backend/api/openapi.yaml` + test kontrak `-run OpenAPI` + `gen:api` (DoD §11).

### Frontend
CompanyPortal `routes/cash-count/`: kartu "Parameter" (tab Kategori Vault — set aktif + riwayat, Kategori ATM Anomaly, Checklist BA, Area) dan kartu "Mapping PIC" (tabel, form, upload CSV dengan pratinjau pola impor master data, unduh CSV). Badge pending + `pendingApprovalMessage()` setelah 202. Layar checker: label entitas baru di `ENTITY_LABELS`, tipe di `PendingEntityType`. Uang `tabular-nums`, rata kanan, "IDR" eksplisit (CLAUDE.md §13).

## Pertanyaan Terbuka & Risiko
- **STCC (K6)** dikeluarkan dari fase ini: diasumsikan atribut vault (keputusan K6) dan dibutuhkan di 5.3. Bila PO menjawab STCC adalah atribut PIC, kolom baru di `cash_count_pics` → AC baru + gerbang 1 diulang.
- Contoh L737 mengkategorikan saldo 1,7 miliar sebagai Medium, bertentangan dengan batas FSD (< 5 miliar = Low). Dianggap contoh lama; tidak mengubah AC-02.
- Engine impor saat ini upsert; mode replace-all (9.1) adalah perilaku baru — bila ternyata engine tidak bisa men-stage `disable` untuk baris yang tidak ada di file tanpa perubahan besar, task 9 → `blocked` dan ditanyakan.
- Menu `cash-count` sudah ada di seed (id 7, "Perhitungan Kas"); label tidak diubah.
