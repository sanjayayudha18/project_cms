# Implementation Plan: Update CIT Forecast Browser

> Enhances the existing Forecast Browser (`/replenishment/forecast-browser`) and its `GET /api/v1/vendor-requests/forecast` endpoint. Three changes: table-owned pagination + page-size selector, cross-page "Pilih Semua Rekomendasi", and four new context columns (Lokasi ATM, Brand, FLM Vendor, FLM Vendor Region). Backend-first, then frontend.
>
> **Dependency (resolved):** "FLM Vendor Region" maps to `vendor_branches.region` — a NEW column added by migration `030_master_atm_esq_columns.sql`, NOT `regions.region` (that is the ATM's geographic area, a different concept) and NOT `vendor_branches.branch_name` (that is the vendor sub-region). Verified against the real MASTER_ATM_ESQ source, which carries `AreaMesin`, `FLMVendorRegion`, and `FLMVendorSubRegion` as three distinct columns. See Task 0.
>
> **Data-population dependency (seed now exists, must be applied):** the FLM Vendor / FLM Vendor Region columns only render real values once the ATM→vendor link is populated. `vendor_packages` and `atm_vendor_packages` were EMPTY in the live schema; the MASTER_ATM_ESQ seed is now written as migrations `030` (adds `vendor_branches.region`, `atms.escrow_account`, `atms.priority_class`), `031` (560 `vendor_packages`, `price=0` placeholder), and `032` (1862 `atm_vendor_packages` links + region/escrow/priority backfills), generated by `scripts/gen_master_atm_esq_seed.py`. NOT yet applied to the DB (external Postgres unreachable). Task 0.5 covers applying + verifying them; the Task 1 integration test depends on it. Until applied, the two columns correctly render the `"-"` placeholder (Req 3.3, 3.6) — the LEFT JOIN returns NULL. This is expected, not a bug.
