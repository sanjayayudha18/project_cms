# Kubernetes (K8s) 101 - Cheat Sheet

> Contoh nama di file ini (`cms-dev`, `cms-prod`, `backend`, `backend-exq`, `eod-retry-scheduler`, dst.) mengikuti draft spec `.kiro/specs/gke-deploy/` (lihat `desain_k8.md`). Manifest-nya belum dibuat, jadi nama bisa berubah.

## 1. Istilah dasar

| Istilah | Arti singkat | Padanan di docker compose |
|---|---|---|
| Cluster | Kumpulan mesin (node) yang dikelola K8s | Satu VM yang menjalankan docker |
| Node | Satu mesin di cluster | VM |
| Namespace | "Folder" untuk memisahkan lingkungan (`cms-dev`, `cms-uat`, `cms-prod`) | Satu project compose |
| Pod | Unit terkecil, berisi 1+ container | Satu container |
| Deployment | Menjaga N pod tetap hidup + rolling update | `services:` + `restart: always` |
| ReplicaSet | Dibuat otomatis oleh Deployment, menyimpan versi pod | Tidak ada |
| Service | Alamat DNS + load balancing ke pod (`backend.cms-prod.svc.cluster.local`) | Nama service di network `cms-net` |
| Ingress | Pintu masuk HTTP(S) dari luar cluster | `ports:` yang dibuka ke host |
| ConfigMap | Config non-rahasia (env, file) | `environment:` / `env_file` |
| Secret | Config rahasia (password DB, `JWT_SECRET`) | `.env` |
| PersistentVolumeClaim (PVC) | Permintaan storage untuk pod | `volumes:` |
| Job | Pod yang jalan sampai selesai lalu berhenti (contoh: migrasi) | `docker compose run --rm` |
| CronJob | Job terjadwal | cron di host |
| Probe | Cek kesehatan: liveness (restart bila gagal), readiness (keluarkan dari load balancer bila gagal) | `HEALTHCHECK` |
| PodDisruptionBudget (PDB) | Batas minimal pod hidup saat node di-upgrade | Tidak ada |
| NetworkPolicy | Aturan siapa boleh memanggil pod mana | Tidak ada |

## 2. Setup awal

```powershell
# Cek versi kubectl
kubectl version --client

# Login ke GKE (sekali per mesin)
gcloud auth login
gcloud components install gke-gcloud-auth-plugin

# Ambil kredensial cluster (nama cluster + region dari tim infra)
gcloud container clusters get-credentials <nama-cluster> --region asia-southeast2 --project <project-id>
```

## 3. Context dan namespace

```powershell
kubectl config get-contexts                     # daftar cluster yang tersimpan
kubectl config current-context                  # cluster yang sedang aktif
kubectl config use-context <nama-context>       # pindah cluster

kubectl get namespaces
kubectl config set-context --current --namespace=cms-dev   # default namespace, supaya tidak perlu -n terus
```

> Selalu cek context sebelum menjalankan perintah yang mengubah sesuatu. Salah context = salah lingkungan (dev vs prod).

## 4. Melihat resource

```powershell
kubectl get pods -n cms-dev                     # daftar pod
kubectl get pods -n cms-dev -o wide             # + IP pod dan node
kubectl get pods -n cms-dev -w                  # pantau terus (Ctrl+C untuk berhenti)
kubectl get deploy,svc,ingress -n cms-dev       # beberapa jenis sekaligus
kubectl get all -n cms-dev                      # hampir semua resource
kubectl get pods -n cms-dev -l app=backend      # filter pakai label

kubectl describe pod <nama-pod> -n cms-dev      # detail + Events (lihat paling bawah saat debug)
kubectl describe deploy backend -n cms-dev

kubectl get deploy backend -n cms-dev -o yaml   # manifest lengkap yang sedang berjalan
kubectl get events -n cms-dev --sort-by=.lastTimestamp
```

Singkatan: `po` = pods, `deploy` = deployments, `svc` = services, `ing` = ingress, `cm` = configmap, `ns` = namespace, `pvc` = persistentvolumeclaim.

## 5. Log

```powershell
kubectl logs <nama-pod> -n cms-dev                  # log satu pod
kubectl logs -f <nama-pod> -n cms-dev               # ikuti terus (seperti docker logs -f)
kubectl logs deploy/backend -n cms-dev              # log salah satu pod dari Deployment
kubectl logs -l app=backend -n cms-dev --tail=100   # semua pod dengan label tertentu
kubectl logs <nama-pod> -n cms-dev --previous       # log container sebelum restart (wajib saat CrashLoopBackOff)
kubectl logs <nama-pod> -c <nama-container> -n cms-dev   # bila pod punya >1 container
kubectl logs <nama-pod> -n cms-dev --since=30m
```

## 6. Masuk ke pod dan akses lokal

```powershell
kubectl exec -it <nama-pod> -n cms-dev -- sh        # shell di dalam container (image Alpine: sh, bukan bash)
kubectl exec <nama-pod> -n cms-dev -- env           # lihat env yang terbaca

# Akses service dari laptop tanpa Ingress
kubectl port-forward svc/backend 8080:8080 -n cms-dev
# lalu buka http://localhost:8080/health

kubectl cp <nama-pod>:/path/file.csv ./file.csv -n cms-dev   # salin file dari pod
```

## 7. Deploy dan update

```powershell
kubectl apply -f deployment.yaml                    # buat atau update dari file
kubectl apply -k deploy/k8s/overlays/dev            # Kustomize (rencana spec gke-deploy)
kubectl diff -k deploy/k8s/overlays/dev             # lihat perbedaan sebelum apply

# Ganti image (tag = git SHA, jangan latest)
kubectl set image deploy/backend backend=<registry>/backend:<git-sha> -n cms-dev

kubectl rollout status deploy/backend -n cms-dev    # tunggu rolling update selesai
kubectl rollout history deploy/backend -n cms-dev   # riwayat revisi
kubectl rollout undo deploy/backend -n cms-dev      # rollback ke revisi sebelumnya
kubectl rollout undo deploy/backend --to-revision=3 -n cms-dev
kubectl rollout restart deploy/backend -n cms-dev   # restart semua pod (misal setelah Secret berubah)
```

> Pod tidak membaca ulang ConfigMap/Secret yang dipakai sebagai env. Setelah mengubahnya, jalankan `rollout restart`.

## 8. Scaling

```powershell
kubectl scale deploy/backend --replicas=2 -n cms-dev
kubectl get hpa -n cms-dev                          # autoscaler, bila dipakai
```

> CROWN: `eod-retry-scheduler` dan `service-dsr-etl` harus tetap **1 replica**. Dua scheduler aktif bersamaan bisa memproses file atau retry dua kali.

## 9. ConfigMap dan Secret

```powershell
kubectl get cm -n cms-dev
kubectl describe cm <nama-cm> -n cms-dev

kubectl get secret -n cms-dev
kubectl describe secret <nama-secret> -n cms-dev    # hanya nama key + ukuran, nilai tidak tampil

# Lihat satu nilai (PowerShell). Jangan tempel hasilnya ke chat, tiket, atau log.
$v = kubectl get secret <nama-secret> -n cms-dev -o jsonpath='{.data.JWT_SECRET}'
[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($v))
```

> Base64 bukan enkripsi. Jangan commit manifest Secret berisi nilai asli ke repo; sumbernya Secret Manager.

## 10. Job (contoh: migrasi DB)

```powershell
kubectl apply -f migrate-job.yaml -n cms-dev
kubectl get jobs -n cms-dev
kubectl logs job/<nama-job> -n cms-dev -f
kubectl wait --for=condition=complete job/<nama-job> --timeout=600s -n cms-dev
kubectl delete job <nama-job> -n cms-dev            # Job selesai tidak terhapus otomatis kecuali ada ttlSecondsAfterFinished
```

> CROWN: migrasi dijalankan di luar jam 07:00-20:00 WIB, urutan `migrate status` → `up` → `status`.

## 11. Debug: status pod yang sering muncul

| Status | Artinya | Cek apa |
|---|---|---|
| `Pending` | Belum dapat node | `describe pod` → Events: resource kurang, PVC belum terikat, node selector |
| `ContainerCreating` lama | Image ditarik atau volume belum ter-mount | `describe pod` → Events |
| `ImagePullBackOff` / `ErrImagePull` | Image tidak ada atau tidak punya izin pull | Nama + tag image, izin Artifact Registry |
| `CrashLoopBackOff` | Container start lalu mati berulang | `logs --previous`, env wajib kosong, DB tidak terjangkau |
| `Running` tapi `0/1 READY` | Readiness probe gagal | `/ready` (DB / replica / Redis), `describe pod` |
| `OOMKilled` | Melebihi batas memori | Naikkan `resources.limits.memory` atau cari kebocoran |
| `Evicted` | Node kehabisan resource | `describe node`, atur `requests` |
| `Terminating` lama | Pod tidak mau berhenti | Tunggu `terminationGracePeriodSeconds`; force delete hanya bila yakin |

Urutan debug cepat:

```powershell
kubectl get pods -n cms-dev
kubectl describe pod <nama-pod> -n cms-dev          # baca bagian Events
kubectl logs <nama-pod> -n cms-dev --previous
kubectl get events -n cms-dev --sort-by=.lastTimestamp
kubectl get endpoints backend -n cms-dev            # kosong = Service tidak menemukan pod siap (cek label/readiness)
```

Tes koneksi dari dalam cluster:

```powershell
kubectl run tmp --rm -it --image=busybox:1.36 -n cms-dev -- sh
# di dalam: wget -qO- http://backend.cms-dev.svc.cluster.local:8080/health
```

## 12. Resource usage

```powershell
kubectl top pods -n cms-dev
kubectl top nodes
kubectl describe node <nama-node>                   # kapasitas + pod yang jalan di node itu
```

## 13. Hapus resource

```powershell
kubectl delete pod <nama-pod> -n cms-dev            # pod dari Deployment akan dibuat ulang otomatis
kubectl delete -f deployment.yaml
kubectl delete -k deploy/k8s/overlays/dev
```

> `kubectl delete namespace <ns>` menghapus **semua** isi namespace, termasuk PVC. Jangan dijalankan di `cms-uat` / `cms-prod`.

## 14. Kerangka manifest minimal

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend
  namespace: cms-dev
spec:
  replicas: 1
  selector:
    matchLabels:
      app: backend
  template:
    metadata:
      labels:
        app: backend                # harus sama dengan selector
    spec:
      containers:
        - name: backend
          image: <registry>/backend:<git-sha>
          ports:
            - containerPort: 8080
          envFrom:
            - configMapRef:
                name: backend-config
            - secretRef:
                name: backend-secret
          readinessProbe:
            httpGet: { path: /ready, port: 8080 }
          livenessProbe:
            httpGet: { path: /health, port: 8080 }
          resources:
            requests: { cpu: 100m, memory: 128Mi }
            limits: { memory: 512Mi }
---
apiVersion: v1
kind: Service
metadata:
  name: backend
  namespace: cms-dev
spec:
  selector:
    app: backend
  ports:
    - port: 8080
      targetPort: 8080
```

## 15. Docker compose → kubectl

| Docker compose | kubectl |
|---|---|
| `docker compose up -d --build` | build + push image, lalu `kubectl apply -k ...` atau `kubectl set image ...` |
| `docker compose ps` | `kubectl get pods` |
| `docker compose logs -f backend` | `kubectl logs -f deploy/backend` |
| `docker compose exec backend sh` | `kubectl exec -it deploy/backend -- sh` |
| `docker compose restart backend` | `kubectl rollout restart deploy/backend` |
| `docker compose down` | `kubectl delete -k ...` (hati-hati, lihat bagian 13) |
| `docker compose run --rm migrate` | `kubectl apply -f migrate-job.yaml` |

Bedanya: K8s tidak build image. Image harus sudah ada di registry (Artifact Registry) sebelum di-deploy.
